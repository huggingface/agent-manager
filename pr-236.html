AGENT MANAGER - PR #236 - BUG FIX
READER: ALWAYS LOAD BACK TO THE LAST PROMPT
LPR
1

INTRODUCTION.

A cold reader pages backward until it holds 20 exchanges, at least 8. Agent output with no prompt above it counts as one exchange, so a long tool-heavy turn used up the budget first and the reader opened on half a turn with no prompt. The fill now keeps going, on its own bounded allowance, until the prompt that opened the latest turn is loaded (figure 1).

2

HOW IT WORKS.

The main reader asks for 20 exchanges (1). After every accepted read, planFill() decides the next step; it is done only when the count is met and the window holds an operator prompt (2), checked by holdsPrompt(), which ignores still-queued prompts (3). Without one it pages back in 1 MiB windows on the FILL_PROMPT_* caps; the server grows a window to one whole record, up to 8 MiB; a Claude compaction summary is a compaction step there, not a prompt (4). Child readers and previews ask for nothing (5). The row the reader opened in keeps its key and holds by its bottom edge as pages land inside it, so opened work stays open and still (6) (figure 2).
